# Shell, SSH, and API Reliability

Before using an authentication reload, import, migration, or refresh flag in a
verification call, trace its complete credential read/write path. A flag named
`forceSessionReload` can import a retained seed file into the active secret store
and overwrite a newer session; it is not necessarily a read-only cache bypass.
Use stored-status reads for read-only verification. Never use a seed import to
suppress automatic recovery. If the supported path would replace credentials,
keep that operation separate and honor the task's credential-change authority.
After an accidental import, preserve the failure and inspect recovery metadata
without exposing secrets; do not infer an upstream permission denial from the
seed's rejection or silently create a replacement session.

Before using a request privacy marker as a cache control, inspect its complete
adapter, policy and fixture behavior. A `sensitive` flag can bypass cassette
replay and recording as well as response caching, making an isolated smoke test
attempt a real provider request. Use an explicitly supported cache directive
such as `cache: no-store` for freshness, and classify authentication separately.
Verify the actual adapter path for anonymous cassette replay, authenticated
no-replay, and independent cache bypass. Keep strict fixtures and existing
privacy protections intact; retain an original failed run and qualify the
corrected path before combined release checks.

Use these rules whenever a command crosses a shell, SSH, HTTP, JSON, or encoding boundary:

1. Identify every parser in the path before running the command, such as PowerShell -> native argv -> SSH -> remote shell -> JSON. Minimize the number of parsing layers instead of adding escapes until a command happens to work.
2. In PowerShell, invoke executables with `&` and an argument array. Prefer literal single-quoted strings for fixed text. Never use `Invoke-Expression`, and do not interpolate untrusted or secret values into command strings.
   Parenthesize each concatenated expression inside an array literal, for example `@('Section', ('Key = ' + $taskValue))`. Commas and `+` can otherwise split a directive from its value into separate records. Validate the serialized structure before activation. For secret-bearing files, validate against a fixed allowlist of directive names and emit only counts or booleans; never print arbitrary malformed lines or inferred key names, which can themselves contain credentials. Replace any exposed credential through its supported rotation mechanism and independently verify the replacement before use.
   PowerShell also recognizes typographic quotation marks as string delimiters. Do not place prose containing curly quotes directly inside quote-delimited command text; use a UTF-8 message/body file or ASCII-only arguments. After a parse failure or empty command result, inspect durable state before retrying to establish whether any earlier operation ran.
   Quote dotted dash-prefixed native options as whole argv values, for example `'-Dorg.gradle.jvmargs=-Xmx2g'`. PowerShell can otherwise split a Gradle system property into `-Dorg` and `.gradle.jvmargs=...`, which Gradle then mistakes for a task. Verify the intended JVM limit is accepted before interpreting that failure as a build or source defect.
   Quote colon-bearing JVM options too, for example `'-XX:ActiveProcessorCount=2'`, or place them in a literal argument array. PowerShell can split an unquoted option into `-XX:` and `ActiveProcessorCount=2`, making Java reject an empty VM option before the build starts. Confirm the actual argv and a bounded `java -version` probe before retrying the guarded workload; retain the failed launch as a shell-boundary failure, not a compilation result.
   Compose a native option containing an object's property as a complete string variable before invocation, for example `$taskOption = 'section.key=' + $taskConfig.value` followed by `git -c $taskOption ...`. An unquoted `section.key=$taskConfig.value` can stringify the whole object and append a literal `.value` instead of passing its property. Verify the exact option through a read-only command before a signed commit, configuration write or other mutation; an invalid signer string is not proof that the configured secret key is missing.
   Quote Git revision expressions containing braces as complete string arguments, for example `'HEAD^{tree}'` and `'v0.6.3^{}'`. In PowerShell argument mode, unquoted braces can become a script block and reach a native program as `-encodedCommand` plus encoded text. Inspect the exact argv/read-only result and check that command's exit status before using a revision or tree comparison as evidence.
   Windows does not expand wildcard path arguments for `rg`. Search a concrete directory with `-g 'pattern'`, or resolve an exact path using `rg --files`, rather than passing paths such as `scripts/deploy*` to `rg`.
3. Never assume the machine's locale or default text encoding. Use UTF-8 explicitly for files, standard input, standard output, subprocesses, and network payloads. On Windows, enable Python UTF-8 mode with `PYTHONUTF8=1` or `python -X utf8` when a tool does not specify its own encoding; set PowerShell and console encodings deliberately when piping non-ASCII text.
    Python `Path.read_text()` can silently decode UTF-8 web assets as Windows cp1252 and corrupt glyphs when they are written back. Pass `encoding='utf-8'` to both reads and writes. If corruption has occurred, recover the characters from the verified original bytes, then version and revalidate the repaired asset; do not repeatedly reinterpret an already corrupted string.
    GitHub Contents API base64 fields may be line-wrapped. Collect and join the complete encoded field before decoding, then emit the decoded UTF-8 text once. Do not decode each PowerShell pipeline record separately: output-record boundaries can insert line breaks inside Markdown words even when the concatenated source bytes are correct. Compare the resulting bytes with the file blob before relying on the document.
    Parse line-oriented native CLI output as validated logical lines before applying full-line patterns. Binary-captured Windows output preserves CRLF, so a multiline `$` pattern can falsely reject an expected field because the carriage return remains. Exercise the actual reader with both LF and CRLF fixtures while still rejecting duplicate, missing, malformed or unexpected authority-bearing fields. Preserve the original failed observer, raw bytes and exit status; recover its analysis offline and run only observations it never reached, without repeating verified downloads or signature checks.
    Bind metadata field names to the selected tool's captured output too. For example, an installed `aapt2` can emit `minSdkVersion` where a reader assumes `sdkVersion`. Test that actual format and reject missing, duplicate or unverified aliases; a parser-only failure does not invalidate successful retained download, signature or manifest commands.
4. Treat native-program exit codes as authoritative. PowerShell may surface native stderr as error records, while tools such as search, Git, and GitHub CLI may use nonzero codes for expected states such as no matches or a missing repository. Interpret each tool's documented result before classifying it as a failure.
   A shipped Android collector can print valid `--help` to stderr and return 1. Retain that exact result and accept it only for the fixed read-only help probe after validating its expected usage text; never extend that exception to trace startup. Select flags from the installed CLI's help, not only rolling online documentation. If that version lacks an atomic no-clobber flag, require an exclusive reservation for the owned producer and an explicit, diagnostic-free absence check on its exact output path before starting. Refuse existing output rather than overwriting a retained trace. Android Perfetto can reject shell-owned temporary config files; use its documented `-c -` configuration input with verified ASCII bytes instead of changing file permissions or SELinux policy. Establish collector readiness before initializing an expensive native workload, and use a fresh validated observation namespace so a failed setup cannot force overwriting or deleting its earlier raw records.
   Verify how a producer samples different clock domains before interpreting their subtraction. Sequential clock snapshots are not simultaneous offsets, and their observed minimum and maximum are not automatically hard alignment bounds. Prefer same-domain markers or source-bound event-order enclosures, retain mapping uncertainty, and reject inconsistent or changing mappings instead of adding an arbitrary timestamp tolerance. Include a sequential-sampling fixture and a contradictory-order rejection case; preserve the original clocks and failed reader result when repairing analysis.
   Keep callback identity separate from a supplied frame timestamp. Choreographer can deliver distinct callback invocations with equal `frameTimeNanos`; preserve each bounded invocation and its actual entry/return clocks, report repeated supplied timestamps separately, and reject true ordering regressions rather than requiring strict timestamp uniqueness. Neither a callback row nor a supplied frame timestamp proves physical composition or display arrival. Test equal supplied timestamps, backward timestamps and raw callback-count reconciliation through the complete reader. If only an incorrect uniqueness assertion rejected completed work, preserve the original failure and reader bytes, then recover verification offline without rerunning the producer.
   Keep workload start separate from the first queried state. A moving target can advance before that query returns. Bind start preconditions to the actual producer's start guard or receipt, then validate the first observation against its own clock enclosure and literal callback/sequence prefix, retaining equal-tick ambiguity. Do not require the target to remain at its start state until a reader arrives, infer start state from a later snapshot, or repeat completed work to repair that observer.
   A pinned terminal record is not necessarily the current settled state. Join it to the producer's actual sequence or attempt count observed at the quiet barrier, require that complete prefix, and preserve lifecycle, cleanup and per-field identity joins. An earlier correct record must not mask a later incorrect submission. Include an earlier-good/later-bad counterexample in the reader controls; preserve completed producer work and repair only offline verification when that observer was insufficient.
   Reconcile runtime-worker inventory separately from measured activity. Nonzero CPU rows omit idle pools, so a scheduled-only list is not a total thread count. Require unique identities and the complete selected query inventory, preserve missing or open interval coverage as unknown rather than zero, and test an inactive worker alongside the positive activity control.
   Derive a collector-closure observer deadline from the verified producer start, configured lifetime and bounded stop grace. Faster measured work can reach a fixed closure wait before the collector's own lifetime ends. Preserve that observer failure, recover already-produced data without rerunning successful work, and keep actual terminal observation separate from inferred expiry or a later export.
5. Validate shell-specific syntax before combining operations. Do not assume Bash syntax works in PowerShell or vice versa. Keep commands fail-fast and check `$LASTEXITCODE` after important native operations so a later successful command cannot hide an earlier failure.
   Validate the generated worker at every interpreter boundary before transport; compiling its generator does not validate embedded source. Use explicit placeholders or one uniquely identified insertion point rather than replacing text that can also occur inside a serialized child program. Preserve a failed payload and determine whether parsing prevented all work before resuming only the repaired observer or unfinished operation.
   A parent PowerShell expands variables inside a double-quoted child `-Command` string before launching that child. An embedded `exit $LASTEXITCODE` can therefore use the parent's old status and report success after a failed child command. Prefer a saved `-File` worker that captures and exits with its own native status; when an inline child script is necessary, pass it as literal source without parent interpolation. Validate the wrapper with a deliberately failing native child as well as a passing one, and keep test-result parsing independent of the wrapper exit.
   An execution working directory applies to the entire command, including subsequent diagnostic reads. Use absolute paths for reports outside that subproject, and separate commands whose working directories differ.
   When composing automation modules with per-run output directories, bind every producer and reader to the same explicit namespace before the first command. A shared executor can write a valid receipt while an imported reader still looks in its previous run's directory. Exercise the actual file-backed missing/present paths and a mismatched-namespace refusal before starting an expensive workload. Preserve a setup-only failure and reconcile completed installations or downloads; resume only unexecuted work with matching retained bytes, not a rebuild or repeat of successful setup.
6. In PowerShell, wrap command or pipeline output in `@(...)` before relying on `.Count`, numeric indexing, or collection comparisons. A single result may otherwise collapse to a scalar, and indexing a string returns a character rather than a path or record.
   Parenthesize each computed array element independently. An expression such as `@($prefix + '-a', $prefix + '-b')` can form an array on the right side of string addition and coerce it into one space-joined string. Use `@(($prefix + '-a'), ($prefix + '-b'))`, or compute separate variables before `@($first, $second)`. Assert both element count and literal names before using the array in an API inventory or file-operation guard.
7. PowerShell statement-style control constructs such as `foreach (...) { ... }` cannot be piped directly. Assign or collect their output first, or wrap the construct in `@(...)` or `$(...)`, before sending it through a pipeline.
8. For SSH, keep the remote command small and fixed. PowerShell OpenSSH commands containing spaces, JSON, pipes, regular expressions, or inline code must use a single-token argument where valid or an exact UTF-8 script encoded as base64 and decoded remotely; do not rely on nested quote escaping. This includes ordinary multiword option values such as deploy reasons: use a delimiter-safe single token when semantics permit, or transport a script when the exact spaces matter. Send secrets and non-ASCII files with a binary-safe file transfer. Base64 is transport encoding, not encryption; never treat it as secret protection.
   Keep large script and asset payloads out of a single command argument. Linux can reject one argument around 128 KiB even when the total command is below `ARG_MAX`. Transfer the payload through standard input or a protected file; for a bounded non-secret bootstrap, compressed source may reduce the argument below the limit. Reconcile remote files before retrying a failed deployment whose wrapper returned no JSON.
   For a bounded compressed bootstrap, compress the actual UTF-8 source and contract representation once before applying outer Base64; encoding each textual member first can waste the argument budget. Measure the complete nested argument emitted by the real transport factory, including its decoder, rather than only the compressed blob. Verify offline that decoding reconstructs every exact source and contract byte/hash, and compile the emitted source as well as its generator. Enforce the existing decoded-size ceiling during decompression and reject truncated streams, trailing data, duplicate/nonfinite JSON and hash mismatches before dispatch. Preserve a local size refusal and establish that it happened before SSH; repair the encoding in a distinct artifact without increasing limits or replaying a producer.
9. Build JSON with a serializer, not manual quote escaping. Send request bodies from standard input or a temporary file with an API client's binary/file-body option. Use proper URL/query encoders rather than concatenating parameters.
   Serialize identity-keyed collections in a deterministic order rather than inheriting set or hash iteration order. When recovering an older retained audit, canonicalize only the explicitly unordered collection by its literal identity and retain duplicate multiplicity; do not sort raw callbacks, geometry members or other causally ordered arrays. Test reordered-equivalent rows, duplicate rows, changed identities and an ordered-series change. Preserve a comparison-only rejection and repair its reader offline without repeating the completed producer.
10. Pass secrets through the provider's credential mechanism, protected files, environment variables, or standard input as appropriate. Do not place credentials, tokens, cookies, private keys, or decoded secret payloads in command history, logs, tracked files, or diagnostic output.
    Treat newly added identity and other private status metadata as private throughout the diagnostic path. Trace every consumer, including subprocesses with inherited stdout/stderr, CI logs and retained captures. Capture and redact or project fields before any logger or artifact write; redacting the final reply does not protect earlier outputs. Test the actual diagnostic producer with nested payloads, malformed output and child failures while preserving health checks, deadlines and exit status. Qualify the hosted log's audience separately. A local redacted copy does not remove provider-held logs; obtain scoped approval before irreversible remote log deletion.
    When supplying a secret through standard input, never allocate a PTY: terminal line discipline can echo the input into captured output even when the receiving script does not print it. Use a plain-pipe process/session with echo disabled, and keep all success/failure output sanitized.
    A tool-managed non-PTY process may close stdin after launch; check that its session supports further input before designing an interactive protocol. If a PTY is needed for non-secret control, keep each control line short and load structured code or data from scoped UTF-8 files. Windows ConPTY can truncate or inject control bytes into long pasted JSON. Keep secrets in owner-protected files and send their bytes only through non-PTY channels; never paste secret-bearing JSON into the control terminal.
11. Before committing in a new worktree, verify repository-local Git identity and remotes. If identity is missing, derive a suitable repository-local identity from the authenticated Git host account when unambiguous; otherwise ask. Do not change global Git identity merely to make one commit succeed.
12. Treat Git-host CLI authentication, HTTPS credentials, and SSH keys as separate transports. A URL-scoped Git credential username can select a different account from the authenticated GitHub CLI and prevent its helper from returning credentials. Check `gh api user --jq .login` and the exact Git credential username configuration, then override the username and helper for that command only; do not switch shared logins or expose tokens. If an `insteadOf` rewrite inserts a different username into the HTTPS URL, a credential-helper override alone is insufficient: use a per-command `url.https://<authenticated-login>@github.com/.insteadOf=https://github.com/` override together with an empty helper followed by `!gh auth git-credential`. Preserve the configured remote and shared authentication. Before an SSH push, verify that the current process can use an authorized key; a logged-in host CLI does not prove SSH access. If SSH is unavailable but the host CLI is authenticated, use its HTTPS credential helper rather than retrying SSH unchanged or exposing a token in a URL or command.
13. Capture the exit code, stderr, and HTTP status before retrying. Treat malformed commands, validation responses, authentication failures, missing tools, locale failures, and quoting/encoding errors as deterministic; fix the cause instead of retrying unchanged.
   For multi-step native producers, persist each completed command's actual exit code and sanitized stdout/stderr before a fail-fast assertion; otherwise a later generic exception loses the failing substage's evidence. If source generation or an earlier validation already succeeded, verify and hash those artifacts, then resume only the unfinished check in a separately named report. Do not regenerate successful geometry merely to obtain diagnostics. Choose a bounded worker memory budget using measured same-runtime needs and headroom while retaining system-reserve and process-tree deadlines. A peak near the enforced memory limit with no reported guard-stop reason is an observation, not proof of the exact native failure cause; reconcile it with the actual command diagnostics before attributing the failure.
    Before a one-use authentication or other non-replayable operation, qualify the private child's failure-reporting path with synthetic errors. Retain exact allowlisted non-secret error categories and status codes bound to the executed producer; unknown stderr must stay in RAM and may yield only a byte count and digest. Keep the primary failure immutable and report cleanup or publication errors separately. If prior error text was discarded, state that its cause remains unknown and use retained sanitized evidence; never repeat consent or another one-use action merely to recover diagnostics.
    For process and socket closure, persist the bounded failed observation before asserting: selected local address and state, socket inode, and owner PID/start identity when available. A closed logical lease or exited worker does not by itself prove that every shared transport socket has closed. Preserve an initial non-closed result, then observe the same unchanged operation at a bounded quiet barrier; keep that later acceptance separate from the producer's original result. Never repeat stop, reload or deployment to repair a closure observer, and do not infer a discarded socket's identity or cause.
    A record-count limit is not a byte or parser-work limit. Large active JSONL logs can contain enormous individual records; prefer indexed summaries and select only needed fields before displaying results. When raw history is necessary, establish file-size and per-record byte limits before decoding, use a bounded reader, and report excluded records as incomplete coverage rather than truncating them into apparent completeness. Keep an explicit deadline for the read itself. If a read stalls, stop only its verified owned process tree; do not repeat the same unbounded parse or treat that observer failure as a failed application workload.
14. Retry only genuinely transient failures such as connection resets, timeouts, rate limits, and selected 5xx responses. Use bounded retries with backoff and honor `Retry-After`. Reads may be retried when safe; never blindly retry a write unless it is idempotent, uses an idempotency key, or remote state is checked first.
    Before invoking a deployment verifier under observation-only authority, trace its complete control flow and any freshness flags. A verifier can request manual refreshes or reindexing and persist data; use a genuinely passive path or obtain the missing authority before invocation. A failed or timed-out incremental refresh can write records before whole-refresh success. Reconcile submission, client outcome, server execution and data effects separately against existing receipts and audit history. A later snapshot or latest-row timestamp can hide overwritten writes; zero matching rows does not establish no effects, and new rows must be included in any bounded comparison. Preserve partial-write evidence and subsequent records, report unavailable request attribution, and do not replay refreshes or restore a whole database merely to repair the observer.

    Recognize every documented success status for an API write, including `201 Created` and `204 No Content`. Save a sanitized completion receipt and any generated identifiers or assigned addresses before validating a dependent response schema or discarding a task-scoped credential. A response-parsing failure does not undo a successful write; reconcile it through an authenticated read before retrying the mutation.
15. When a cross-boundary command fails, reduce it to the smallest read-only probe and validate each boundary independently: local serialization and encoding, executable availability, transport connectivity, remote interpreter, authentication, then the final operation.
16. Preserve bundled, vendored, and unrelated user files. If a check reports a pre-existing formatting issue in such a file, isolate and report it instead of silently rewriting upstream content or weakening checks for the files being changed.
17. Verify state after remote writes using a separate read. Report the exact layer that failed and preserve useful sanitized diagnostics instead of labeling every failure as transient.
    Before claiming storage durability, inspect the cache-policy semantics and verify the record through the durable query/read path. Memory-only flags can look persistent in an inaccurate mock; keep mocks faithful to the storage contract and test reuse after replacing the storage process's memory cache.
18. Keep Windows PowerShell 5.1 and its older .NET surface in mind. For portable in-memory SHA-256, use `SHA256.Create().ComputeHash(...)` plus `BitConverter.ToString(...)`; newer conveniences such as `SHA256.HashData` and `Convert.ToHexString` may be unavailable.
   For legacy Windows compilers such as .NET Framework `csc.exe`, pass absolute input and output paths with native backslash separators. Forward-slash paths can be reparsed as option or file boundaries. Compare the reported source filename with the verified input before changing source or blaming a missing artifact; retain a failed compilation and launch only the successfully produced, scoped executable.
   The same compatibility constraint applies to path helpers: `System.IO.Path.GetRelativePath()` may be unavailable. For a verified child path, normalize the root with a trailing directory separator, require an ordinal-ignore-case prefix match, then take the substring and normalize separators; do not silently fall back to unchecked string replacement.
19. `gh api -f` supplies request fields and can select a write method unless the method is explicit. For read-only GitHub API queries with fields such as `ref`, pass `-X GET` and verify the returned HTTP status before parsing the body.
20. Do not reuse PowerShell automatic variable names such as `$PID`, `$HOME`, `$Host`, `$Error`, `$Matches`, or `$Input` for task state. In particular, `$Input` can silently retain pipeline-enumerator semantics and make path-length or substring calculations operate on the wrong value. Use task-specific names (`$amazonPid`, `$captureRoot`, `$inputRoot`, `$probeResult`) so assignments cannot fail or clobber shell state.
21. When serializing native-command output, keep PowerShell error records out of the data stream. Some native tools write progress or diagnostics to stderr, which PowerShell can surface as `NativeCommandError`; redirect or suppress expected progress separately, and serialize only controlled stdout/status objects.
22. Windows PowerShell 5.1 writes a UTF-8 BOM with `Set-Content -Encoding utf8`. For JSON, HAR, cURL captures, or other inputs consumed by strict parsers, use the repository writer or `[IO.File]::WriteAllText($path, $text, (New-Object Text.UTF8Encoding($false)))` when a BOM-free UTF-8 file is required.
    When reading an existing CSV, verify its encoding marker before indexing header names. A UTF-8 BOM decoded as plain `utf-8` becomes part of the first header (for example, `\ufeffReference`) and can cause a misleading missing-column error. For a verified UTF-8 source with an optional BOM, use `utf-8-sig` in the scoped reader; preserve and hash the original bytes rather than rewriting the file to accommodate the parser. Include BOM-bearing and BOM-free header fixtures.
23. Do not call string methods on optional native output without a null guard. A missing device line, empty command result, or failed probe can make `.Trim()`, `.Split()`, or indexing throw before the real transport state is reported.
    PowerShell HTTP response `.Content` can be a byte array rather than a string, depending on the response media type. Check its type before calling string methods; decode verified textual metadata with an explicit encoding (for example, UTF-8 for a checksum response), then validate its expected shape. Do not stringify a byte array or assume an HTTP success response is decoded text.
24. Frida and other prompt-toolkit/interactive CLIs on Windows may require a real PTY. If a read-only CLI probe fails with console or prompt-toolkit errors under plain pipes, rerun it with a PTY before changing the target process or transport setup.
25. When a package runner or control CLI prints its invocation before a JSON response, do not parse from the first `{`; echoed JSON arguments may appear there. Prefer a machine-readable or silent mode when available. Otherwise isolate the final response object with a validated delimiter or parse the last complete JSON document, then verify its expected top-level keys before using it.
    GitHub CLI Actions log reads can share a per-run ZIP cache. Do not populate that cache concurrently with multiple `gh run view --log` or `--log-failed` calls for jobs in the same run. If a ZIP/cache-reader failure occurs, preserve its exit status and diagnostics, reconcile the completed workflow and job identities, and retrieve the selected logs through the direct job-log API or one serialized run-log download. Do not rerun passing jobs or broadly delete shared CLI caches to repair a log observer.
    GitHub Actions text logs from `gh run view --log` use job, step, and timestamp-plus-body fields separated by tabs. Validate the captured layout before parsing; individual job payloads can retain a UTF-8 BOM immediately before the timestamp, and ANSI formatting can appear as literal caret-escaped sequences. Remove only the observed formatting at its defined boundary. Scope deployment receipts to the actual production job and step so passing synthetic test messages cannot establish that promotion or restart occurred. Preserve raw logs and parser refusals, and repair only offline extraction without replaying the completed workflow.
26. When running Node.js source from standard input in a package that uses ES modules, do not mix CommonJS `require()` with top-level `await`; Node treats that syntax as ambiguous. Use ESM `import` with `--input-type=module`, or keep CommonJS and wrap asynchronous work in an async function or IIFE. To consume piped standard input by numeric file descriptor, use `readFileSync(0, "utf8")` from `node:fs`; current Node releases do not accept fd `0` as a path in `node:fs/promises.readFile()`.
    Windows absolute paths are not ESM import specifiers: `C:/...` is parsed as an unsupported `c:` URL scheme. Convert computed paths with `pathToFileURL(path).href` before dynamic import, or use a valid `file:///C:/...` URL for a fixed import. Keep ordinary filesystem paths for filesystem APIs. After a loader refusal, repair only the import boundary and resume the unchanged workload.
27. In PowerShell, suppress return values from .NET methods that return request or response objects when those objects may contain credentials in headers. Assign the result or cast it to `[void]`; for example, do not leave `HttpResponseMessage.EnsureSuccessStatusCode()` as an unassigned statement because PowerShell will print the full response, including request headers.
28. Windows PowerShell may decode a piped string into records and write native standard input with platform line endings, even after the in-memory text was normalized to LF. When a remote script requires byte-exact LF endings, encode its UTF-8 bytes as base64 locally and decode them into the remote interpreter instead of piping the PowerShell string directly.
    Python text-mode subprocess input on Windows can also translate LF to CRLF. For byte-sensitive local protocols such as a Git patch against LF blobs, pass UTF-8 `bytes` through binary subprocess input rather than `text=True`; validate with `git apply --check` before applying. Do not compensate for a transport newline change by weakening patch-context matching.
29. A shell-command timeout on Windows may terminate only the PowerShell wrapper while leaving native child processes running. For long-lived Java, router, renderer, simulator, or similar jobs, launch with `Start-Process -WindowStyle Hidden -PassThru`, retain the exact returned PID, poll that PID explicitly, and terminate only that verified process if the operation times out or is cancelled. Do not assume a wrapper timeout killed descendants, and do not clean up by broad process-name matching.
30. After cancelling or terminating a yielded command cell, treat wrapper completion as unrelated to descendant cleanup. Before relaunching, inspect the retained child PID and its process tree, verify each target by executable path, command line, parent PID, and start time, then stop only that validated tree and confirm it exited. Parent PIDs can be stale after PID reuse, so exclude any apparent child whose creation time predates the recorded parent launch; a matching `ParentProcessId` alone is never sufficient. Never use a broad process-name kill to compensate for an orphaned child.
31. Windows PowerShell 5.x does not support the PowerShell 7 null-coalescing operator `??`. For scripts that must run on the default Windows host, use `ContainsKey()`, explicit `$null` checks, or conditional assignment instead of `??`, and parse-check with the target PowerShell version before launching long-running work.
32. When checking cookbook freshness in a dirty worktree, compare the committed blob to the upstream blob separately from the working copy. A local working-file hash that differs from upstream may be an intentional uncommitted user change; do not stage, overwrite, or describe it as stale without inspecting both diffs.
33. On Windows, run FreeCAD Python automation with the bundled `bin\\python.exe`, not `FreeCADCmd.exe`, when the script needs ordinary `argparse` options. `FreeCADCmd.exe` consumes unknown switches as application options unless its version-specific pass-through syntax is handled exactly. For a long FreeCAD build, launch or monitor the bundled Python process by exact PID because a shell timeout can leave it running.
34. PowerShell `-LiteralPath` never expands wildcard characters. To copy every child of a directory while retaining literal-path safety, enumerate with `Get-ChildItem -LiteralPath $source` and pass each returned `.FullName` to `Copy-Item -LiteralPath`; then compare an enumerated relative-path/size/hash manifest before relying on the snapshot. Do not combine `-LiteralPath` with `*` and assume files were copied.
35. When loading a Python module manually with `importlib.util.module_from_spec()` and `spec.loader.exec_module()`, register it in `sys.modules[spec.name]` before executing the module body. Decorators such as `@dataclass` may resolve annotations through `sys.modules` during import and fail with a misleading `NoneType.__dict__` error when the registration is omitted.
36. Do not `source` or dot-invoke dotenv/application env files in a shell unless the owning format explicitly guarantees shell syntax. Unquoted spaces, parentheses, hashes, and provider-specific values may be valid to the application's parser but invalid or meaning-changing in Bash or PowerShell. Use the application's normal config loader, a dotenv parser, or a narrow parser that reads only the required key without printing secret values.
    Trace whether that loader hydrates environment files only for its default process-environment object. Passing a copied environment can skip hydration and select a fallback backend even when the service is configured correctly. Use the loader's supported hydration path under the verified service working directory, keep secret values in memory, and compare non-secret backend identity before opening storage. Preserve the original pre-query refusal and resume only the unexecuted read; do not migrate, reconfigure or retry against an unqualified fallback.
37. Catch browser-automation exceptions before printing or serializing them when their messages may include DOM excerpts, request URLs, or element snapshots. Report only a sanitized exception type and a bounded, manually selected summary; Playwright and similar tools can embed short-lived signed URLs, private page text, cookies, or other session material in otherwise routine timeout and actionability diagnostics.

In PowerShell, pass Gradle project properties containing dotted names and an equals sign as one explicitly quoted argument, especially instrumentation selectors such as `'.\\gradlew.bat connectedDebugAndroidTest'` arguments of the form `'-Pandroid.testInstrumentationRunnerArguments.class=com.example.Test'`.
